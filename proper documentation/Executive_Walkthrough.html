Git In Bits: Executive Roadmap v2

This document outlines the strategic roadmap, updated based on recent architectural feedback. Core Rule: The existing AI Chatbot and its data dependencies will remain completely untouched and fully functional.

Level 1: The "Mota-Mota" Organization Dashboard

The Vision

A beautiful, uncluttered dashboard showing org-level activity. Instead of just listing "bugs" and "features", it should generate intelligent, human-like briefs: "The backend crashed yesterday but was fixed within minutes," or "The UI team achieved a major milestone." Filterable by time (1 day, 3 days, 1 month).

Engineering Feasibility & Path Forward

Because GitHub does not inherently know if a "backend crashed" unless someone writes it in an issue or commit, we cannot do this with simple math. We must use an Asynchronous AI Summarizer.

How we will build this:
  • Backend Cron Job: We create a nightly background task that gathers every commit, PR, and Issue created across the organization that day.
  • AI Aggregation: It feeds this raw data to a secondary, "faceless" AI agent (using the exact same Groq API key, but a different prompt).
  • Database: The AI generates a clean paragraph summarizing the day's achievements and crises. We save this in MongoDB as an OrgDailySummaryDoc.
  • Frontend: The dashboard simply queries these pre-calculated summaries, meaning the dashboard loads instantly without waiting for AI generation.

Level 2: Developer-Wise Tracking (UI)

The Vision

A clean list view showing each developer in the organization. Their face (avatar) is on the left, and a brief overview of their recent activity is on the right.

Engineering Feasibility & Path Forward

This is highly feasible and mostly a Frontend UI task, supported by a new backend aggregation query.

How we will build this:
  • Avatars: GitHub automatically provides developer avatars via a public URL structure.
  • Backend: We will build a GET /api/developers endpoint that groups MongoDB commits by authorName and returns their latest 5 activities.
  • Frontend: We will build a beautiful new React component (e.g., DeveloperList.tsx) designed exactly to your specifications.

Level 3: Developer Efficiency Report (UI Integration)

The Vision

Clicking on a developer generates a full AI analysis of their true efficiency and coaching needs. Crucially, this is displayed directly on the UI card, NOT inside the chatbot widget.

Engineering Feasibility & Path Forward

We do not need two API keys. We can use the same Spring AI infrastructure to power both the chatbot and UI widgets seamlessly.

How we will build this:
  • Data Upgrade: We will carefully add file-level diff stats (lines added/removed) to the GitHub sync process. (This will be strictly additive, so the old AI chatbot does not break).
  • New REST Endpoint: We will create GET /api/developers/{name}/ai-summary.
  • Behind the Scenes: When the UI hits this endpoint, the backend quickly asks Groq for an "Efficiency Review" using the new stats, and returns a Markdown string.
  • Frontend: The UI renders this Markdown string directly in the developer's profile card, completely bypassing the chatbot widget.
